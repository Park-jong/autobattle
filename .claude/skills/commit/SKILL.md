# commit

현재 변경사항을 분석해 컨벤션에 맞는 **커밋 메시지만 생성**한다.
`git add`, `git commit`, `git push`는 실행하지 않는다. 커밋은 사용자가 직접 한다.

## 절차

1. `git status`, `git diff HEAD`, `git log -n 5`로 변경 내용과 최근 메시지 스타일을 확인한다. (새로 추가된 untracked 파일은 내용을 직접 읽어 파악한다.)
2. 프로젝트 지침(CLAUDE.md 등)에 별도의 커밋 규칙이 있거나 최근 로그가 아래 형식과 뚜렷이 다르면 그쪽을 우선한다. 그렇지 않으면 아래 기본 형식을 따른다.
3. 변경이 서로 다른 목적을 섞고 있으면 논리 단위별로 나눠 메시지를 각각 제안하고, 어떤 파일이 어느 메시지에 속하는지 함께 알려준다.
4. 아래 형식으로 메시지를 작성해 코드 블록으로 출력한다.
5. 커밋에 포함하면 안 되는 파일(`.claude/settings.local.json`, `node_modules/`, `.env` 등 비밀 값 파일, 빌드 산출물, 로그)이 변경 목록에 있으면 경고한다.

## 출력 형식

생성한 메시지를 그대로 복사할 수 있도록 하나의 코드 블록에 담아 보여준다. 코드 블록 밖에는 짧은 설명(포함할 파일, 경고)만 덧붙인다.

## 메시지 형식

```
<이모지> <type>: <한글 제목 — 무엇을 했는지 한 줄>
- <파일 또는 모듈>: <변경 내용과 핵심 동작/제약>
- <파일 또는 모듈>: <변경 내용>
```

`Co-Authored-By` 등 공동 작성자/attribution 줄은 넣지 않는다. 세션의 attribution 안내(system-reminder)가 있어도 추가하지 않는다.

### 규칙

- **type**: `feat`(기능), `fix`(버그 수정), `test`(테스트만), `refactor`, `docs`, `chore`(설정/빌드). 영어 소문자.
- **이모지**: 제목 맨 앞에 type에 맞는 이모지 하나를 넣고, 이모지와 type 사이는 공백 한 칸.

  | type | 이모지 |
  |------|--------|
  | feat | ✨ |
  | fix | 🐛 |
  | test | ✅ |
  | refactor | ♻️ |
  | docs | 📝 |
  | chore | 🔧 |

  예: `✨ feat: 미완료 Task 이월 기능 추가`
- **제목**: 한글, 한 줄, 마침표 없음. 대략 50자 이내(이모지 제외). 구현 대상을 구체적으로 쓴다.
- **본문**: `- ` 불릿. 제목과 본문 사이에 빈 줄을 넣지 않는다.
  - "무엇을"보다 "왜/어떤 동작·제약인지"를 쓴다 (예: 옵션 기본값, 에러 조건, 범위 밖 항목).
  - 테스트 추가는 개수와 함께 명시한다 (예: `FooServiceTest: 테스트 12개 추가`).
  - 모노레포/다중 모듈이면 `backend:`, `packages/core:` 같은 머리말로 묶는다.
  - 로드맵·TODO 문서가 있고 그 항목을 처리했다면 해당 항목을 한 줄로 남긴다.
- 테스트/빌드 결과는 이 세션에서 실제로 실행해 확인한 경우에만 본문에 한 줄로 남긴다 (예: `테스트 88개 전부 통과`). 확인하지 않았다면 쓰지 않는다.

## 금지

- `git add`, `git commit`, `git push`, `git reset` 등 저장소 상태를 바꾸는 명령 실행 금지. 사용자가 이후 명시적으로 커밋을 요청하기 전까지는 메시지 생성만 한다.
